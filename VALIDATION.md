## Version 2.3 failure handling and stress coverage

- Completion now runs ffprobe on the nonempty output and requires H.264 video plus AAC audio in an MP4 container, or MP3 audio without video in an MP3 container. A 30-second deadline bounds this check; cancellation stops its process tree. Invalid files remain on disk and are not recorded as completed or added to history. This inspects container and codec metadata, not every decoded frame. Existing unreadable output must be moved aside before Retry because downloads use `--no-overwrites`.
- Process isolation now terminates leftover descendants when the engine's root exits, preventing a child that still writes to an inherited output pipe from hanging the worker indefinitely. Tests exercise a real noisy descendant, a silent timeout, normal exit codes, Unicode arguments and process-tree cancellation.
- The crash test launches an independent owner process using the production process runner, waits for its child to write partial bytes, then forcibly kills only that owner. Kill-on-close job cleanup stops the writing child, partial data stays intact, and a fresh state load restores unfinished work as paused while retaining history. This tests abrupt process death; it does not reboot Windows or simulate loss of power.
- Real Windows read-only primary/backup attributes and an exclusively locked staged file exercise state-write failures. The committed primary survives each failure, and saving succeeds after access is restored. Read-only primary files are now rejected before backup copying, avoiding an inherited read-only attribute on the backup. Pause preserves an actionable persistence error instead of replacing it with the normal paused message.
- A synthetic 5,000-entry playlist passes through the actual bounded worker mailbox and native list. Bulk and individual selection are checked. A 100-item subset runs through the real App dispatcher with deterministic fake yt-dlp/ffprobe executables; completion, files, persisted history and duplicate prevention are checked. The final run loaded the playlist in 6.422 seconds and completed the fixture queue in 31.297 seconds; peak mailbox size was 2,048 and the longest observed drain batch was 281 ms. These are application queue tests, not 100 real media downloads or a hardware-independent benchmark. Measurements are in `tests/results/stress-result.json`.
- Real yt-dlp and FFmpeg produced MP4/MP3 from generated local media. The production validator accepted both, rejected nonempty corrupt files using real ffprobe, and left those corrupt files byte-for-byte unchanged. Evidence: `tests/results/release-2.3-media.log`.
- A local HTTP server injected two 503 responses, forced engine termination, a connection drop partway through the response, and a server ignoring a resume Range request. Real yt-dlp recovered or restarted as appropriate. All three final 8,410,578-byte files matched the source SHA-256. The interrupted transfer resumed at 1,047,552 bytes; the dropped connection resumed at 130,048 bytes. Evidence: `tests/results/release-2.3-recovery.log` and `tests/results/http-recovery/result.json`, with individual engine logs alongside the report. This tests local HTTP recovery, not a live YouTube outage.

## Release boundaries

The build is unsigned. Overnight live playlist runs, interruption during a live YouTube transfer, actual Windows restart/power loss during a transfer, physically full disks, sustained destination permission loss, multi-machine testing and import/playback in a specific ShowDeck build have not been exercised here. Read-only/locked state files and abrupt process termination were tested as described above. Byte-range recovery was verified against a local server; real sources may restart a stream, merge or conversion. The validation establishes the tested behavior; it is not production certification or a guarantee against future service changes and all machine/network failures.

The source ZIP contains the complete Visual Studio solution, sources, resources, tests and scripts. The executable ZIP includes a hash manifest and dependency setup script; external engines are installed separately. The local verified build already has the engines installed. Packaging verifies the ZIP entries and binary-package content hashes.
